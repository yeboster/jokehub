## Goal

Seven rounds have polished the paths a user walks on purpose: the feed, the joke page, the forms,
the dialog. This round covers the ones they arrive at by accident or from outside — a link pasted
into a chat window, a crashed render, a URL that no longer resolves, a crawler, a printer — plus
the six behaviours round 7 recorded and consciously did not fix.

Concretely, the app today:

* has **no error boundary anywhere** (`find src/app -name 'error.tsx' -o -name 'global-error.tsx'`
  → nothing). A throw inside any client page reaches Next's built-in error screen, which is an
  unstyled `Application error: a client-side exception has occurred` with no way back.
* has **no `not-found.tsx`**, so `/jokez` gets Next's default 404 — no nav, no wordmark, no link
  into the app.
* has **no `metadataBase`, no `openGraph`, no `twitter`** metadata. Round 7 shipped a "Copy link"
  button whose whole purpose is pasting a joke URL somewhere else; pasted into Slack, iMessage,
  WhatsApp or a Discord channel it unfurls as a bare URL with no title, no description and no
  image.
* has **no `robots.ts` and no `sitemap.ts`**, so a crawler is free to index `/add-joke`,
  `/edit-joke/<id>` and `/auth`, none of which do anything for a signed-out visitor.
* ships **ten packages nothing imports** and one orphaned shadcn primitive (`ui/tooltip.tsx`,
  recorded as orphaned in round 7 with "no action").
* has **no print styles** (`grep -rn '@media print' src/` → nothing). A comedian printing a set
  list gets the sticky navigation bar on the sheet and a card that can break mid-punchline.

And from round 7's *Known behaviour recorded, not fixed*: the empty-state hint is announced by
nothing, the joke-not-found branch announces nothing, `CopyLinkButton`'s timer has no cleanup and
no reset, the share control is visually quieter than Back, the account icon keeps a trailing
margin at widths where its label is hidden, and the dialog close button leaves the screen on a
short scrolling viewport.

Sixteen tasks. One commit each. Read-only review between batches.

## Architecture

Nothing structural changes. The round adds four App Router convention files at the root of
`src/app/`, one pure module in `src/lib/`, and one function to each of two existing pure modules.
Everything else is a class string or a handful of lines in an existing component.

The three conventions this repo already runs on, and that this plan obeys:

1. **Logic goes into a pure `src/lib/` module with a vitest suite.** There is no React Testing
   Library here and this round does not add one. Anything with a decision in it — resolving a
   site URL from three environment variables, joining an empty state's two sentences, deciding
   what a failed joke load should say — becomes an exported function that is tested directly.
   Components then hold wiring only. `src/lib/` is outside Tailwind's content globs
   (`tailwind.config.ts:5-9` lists `src/pages`, `src/components`, `src/app` only), so **nothing in
   `src/lib/` may return a class name**.
2. **A live region announces text that *changes* after it is already in the DOM.** A region
   mounted with its message never announces. Round 6 established the rule, round 6's `af11636`
   erratum and round 7's Task 11 applied it. Two tasks here depend on it (9 and 10).
3. **Comments are prose, not class syntax.** Tailwind's scanner reads comments in every file under
   the content globs, and several rounds now carry verification greps that a comment quoting a
   class would defeat. Write "the max-height bound" and "an arbitrary font size", never the
   literal utility.

### Step 3 — the implementation

Create `src/lib/siteUrl.ts`:

```ts
/**
 * Where this deployment lives.
 *
 * Three consumers need an absolute origin and none of them can ask the browser
 * for one: `metadataBase` in the root layout, the `Sitemap:` line in
 * `robots.txt`, and every entry in `sitemap.xml`. All three are produced on the
 * server, at build time, where `location` does not exist.
 *
 * Precedence, most specific first:
 *
 *   1. `NEXT_PUBLIC_SITE_URL` — set this by hand once the app has a real domain.
 *      It is the only one that survives a change of hosting provider.
 *   2. `VERCEL_PROJECT_PRODUCTION_URL` — the project's stable production host,
 *      the same on every production deployment.
 *   3. `VERCEL_URL` — the per-deployment host. Different on every push, so a
 *      preview build's metadata points at the preview, which is what you want
 *      when you are checking a link card before shipping it.
 *   4. The dev server's origin.
 *
 * Strings only: `src/lib/` is outside Tailwind's content globs
 * (`tailwind.config.ts`), so nothing here may return a class name.
 */

/** The dev server's origin — `npm run dev` binds port 9002 (`package.json`). */
export const DEV_SITE_URL = 'http://localhost:9002';

/** The environment variables this module reads, as a plain injectable object. */
export interface SiteUrlEnv {
  NEXT_PUBLIC_SITE_URL?: string;
  VERCEL_PROJECT_PRODUCTION_URL?: string;
  VERCEL_URL?: string;
}

/**
 * A hostname becomes an https origin; an origin that already states its scheme
 * keeps it (a tunnel or a LAN address is http and must not be rewritten).
 * Trailing slashes go, so a caller can concatenate a path without producing a
 * doubled slash — the same rule `jokeShareUrl` follows in `src/lib/share.ts`.
 */
function normalizeOrigin(value: string): string {
  const withScheme = /^https?:\/\//i.test(value) ? value : `https://${value}`;
  return withScheme.replace(/\/+$/, '');
}

/**
 * The absolute origin for this deployment, never with a trailing slash.
 *
 * Takes its environment as an argument so it is testable without touching the
 * real `process.env`; `SITE_URL` below is the one place that supplies the real
 * one.
 */
export function resolveSiteUrl(env: SiteUrlEnv = {}): string {
  const candidates = [
    env.NEXT_PUBLIC_SITE_URL,
    env.VERCEL_PROJECT_PRODUCTION_URL,
    env.VERCEL_URL,
  ];

  for (const candidate of candidates) {
    const trimmed = candidate?.trim();
    // A Vercel environment variable that was declared and left blank arrives as
    // an empty string, not as undefined.
    if (trimmed) return normalizeOrigin(trimmed);
  }

  return DEV_SITE_URL;
}

/**
 * The resolved origin for this process. Read once at import time from
 * explicitly named members of `process.env` rather than from the object as a
 * whole: Next inlines `process.env.SOMETHING` at build time only for static
 * member access, and passing the object would silently stop working if this
 * module were ever pulled into a client bundle.
 */
export const SITE_URL = resolveSiteUrl({
  NEXT_PUBLIC_SITE_URL: process.env.NEXT_PUBLIC_SITE_URL,
  VERCEL_PROJECT_PRODUCTION_URL: process.env.VERCEL_PROJECT_PRODUCTION_URL,
  VERCEL_URL: process.env.VERCEL_URL,
});
```

# Task 3 — `robots.txt`

**Objective.** A crawler currently has no guidance at all, so `/add-joke`, `/edit-joke/<id>`,
`/manage`, `/auth` and the four API routes are all fair game. None of them render anything useful
to a signed-out visitor — `/edit-joke/<id>` renders a permission error — and indexing them spends
crawl budget on dead ends and puts a login form in search results.

**Files**

* create `src/app/robots.ts`

**No test.** A single object literal; the only computed value is `SITE_URL`, tested in Task 1.

### Step 1 — the implementation

Create `src/app/robots.ts`:

```ts
import type { MetadataRoute } from 'next';

import { SITE_URL } from '@/lib/siteUrl';

/**
 * Next serves this at `/robots.txt`.
 *
 * The disallow list is every route that needs a session to mean anything. They
 * are not secret — `firestore.rules` decides what is readable, not this file,
 * and a crawler ignoring robots.txt still gets a permission error. The point is
 * that a login form and an edit form have no business in a search result, and a
 * crawler walking `/edit-joke/<id>` for every joke spends the crawl budget that
 * should have gone to the feed.
 */
export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/api/', '/add-joke', '/edit-joke/', '/manage', '/auth'],
    },
    sitemap: `${SITE_URL}/sitemap.xml`,
  };
}
```

```ts
import type { MetadataRoute } from 'next';

import { SITE_URL } from '@/lib/siteUrl';

/**
 * Next serves this at `/sitemap.xml`.
 *
 * Two entries, deliberately. The public surface of this app is the landing page
 * and the feed; everything else either needs a session or is a single joke.
 *
 * Per-joke URLs are *not* here. Listing them means reading the collection at
 * build time through the Admin SDK, which is the same data-layer change a
 * per-joke `<title>` needs and which rounds 6 and 7 both deferred — and a
 * build-time list goes stale the moment somebody adds a joke. `/jokes` links to
 * every joke, so a crawler reaches them all from here in one hop.
 *
 * No `lastModified`: stamping it with the build time would report a change on
 * every deploy whether or not anything changed, which is exactly the signal it
 * is supposed to carry.
 */
export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: `${SITE_URL}/`,
      changeFrequency: 'daily',
      priority: 1,
    },
    {
      url: `${SITE_URL}/jokes`,
      changeFrequency: 'daily',
      priority: 0.8,
    },
  ];
}
```

# Task 5 — a route error boundary

**Objective.** Every page in this app is a client component that fetches in an effect. A throw
during render — a joke document with an unexpected shape, a context read before its provider, a
null dereference in a `useMemo` — currently unmounts the whole tree and shows Next's built-in
client-exception screen: unstyled, no navigation, no wordmark, and no way back except the browser
button. `error.tsx` replaces the failed segment's content while the root layout (navigation,
theme, toasts) stays mounted, and offers `reset()`, which re-renders the segment without a full
page reload.

**Files**

* create `src/app/error.tsx`

**No test.** A React error boundary cannot be exercised without a renderer, and this repo has no
React Testing Library (rounds 3-7 all met the testing obligation by extracting *logic*; there is
no logic here — the copy is static and `reset` comes from Next). Verified by build, lint and a
manual throw.

### Step 1 — the implementation

Create `src/app/error.tsx`:

```tsx
"use client";

import { useEffect } from 'react';
import { AlertTriangle } from 'lucide-react';

import EmptyState from '@/components/EmptyState';
import { Button } from '@/components/ui/button';

/**
 * The error boundary for every route below `src/app/`.
 *
 * Next requires this to be a client component: it holds the boundary itself and
 * the `reset` callback. It replaces the failed segment's content only — the root
 * layout stays mounted, so the navigation, the theme and the toaster survive and
 * the user is still somewhere rather than nowhere.
 *
 * It deliberately does *not* render the error message. Six of the seven routes
 * fetch from Firestore, and a raw exception string can carry a document id or a
 * rule name; `digest` is the handle a developer needs and it is already in the
 * console line below and in the server logs.
 *
 * This does not catch a throw in the root layout — nothing below the layout can.
 * `global-error.tsx` does.
 */
export default function RouteError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error('Unhandled error in a route segment:', error);
  }, [error]);

  return (
    <div className="container mx-auto px-4 py-8 sm:px-6 md:py-12">
      <EmptyState
        icon={AlertTriangle}
        // The page's only heading: this branch renders no Header, exactly like
        // the joke-not-found branch.
        titleAs="h1"
        title="Something went wrong."
        hint="This page hit an unexpected error. Trying again reloads just this section — the rest of the app is fine."
        action={<Button onClick={reset}>Try again</Button>}
      />
    </div>
  );
}
```

# Task 6 — a root error boundary

**Objective.** Task 5's boundary lives *inside* the root layout, so it cannot catch a throw in the
root layout itself — from `ThemeProvider`, `AuthProvider`, `JokeProvider`, `Navbar` or the font
loader. That case currently produces a blank white document. `global-error.tsx` replaces the whole
document, which is why it has to render its own `<html>` and `<body>`.

**Files**

* create `src/app/global-error.tsx`

**No test.** Same reasoning as Task 5.

### Step 1 — the implementation

Create `src/app/global-error.tsx`:

```tsx
"use client";

import { useEffect } from 'react';

import { Button } from '@/components/ui/button';

// The root layout is what failed, so its stylesheet import went with it. This
// one is ours.
import './globals.css';

/**
 * The boundary of last resort: a throw in the root layout itself — a provider,
 * the navigation bar, the font loader. It replaces the entire document, so it
 * renders its own html and body, and it runs with none of the app's providers.
 *
 * Two consequences, both accepted rather than worked around:
 *
 *   - No theme provider, so this page is always light. Adding one would mean
 *     mounting the provider that may be the thing that just crashed.
 *   - No font variable on the body, so it renders in the system sans face. The
 *     stylesheet above still supplies the colour tokens and the type scale.
 *
 * `Button` is safe here: it is a plain forwardRef with no hooks and no context.
 */
export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error('Unhandled error in the root layout:', error);
  }, [error]);

  return (
    <html lang="en">
      <body className="antialiased bg-background text-foreground">
        <main className="container mx-auto flex min-h-screen max-w-xl flex-col items-center justify-center px-4 py-8 text-center sm:px-6 md:py-12">
          <h1 className="text-3xl font-bold tracking-tight sm:text-4xl">Joke Hub didn’t load.</h1>
          <p className="mt-3 text-base text-muted-foreground sm:text-lg">
            Something failed before the page could start. Reloading usually fixes it.
          </p>
          <div className="mt-6">
            <Button onClick={reset}>Reload</Button>
          </div>
        </main>
      </body>
    </html>
  );
}
```

```ts
/**
 * The empty feed as one announced sentence.
 *
 * The visible block stacks the headline above the hint and a sighted user reads
 * both. A live region has no layout: it announces the text it holds, so the two
 * lines are one utterance or the second one reaches nobody. The feed's region
 * spoke the headline alone until now, which meant every instruction this module
 * writes — how search tokenizes, that filters can be cleared, that a failed
 * fetch can be retried — was invisible to a screen reader.
 *
 * Both strings already end in a full stop (pinned by this module's suite), so a
 * single space is the whole join.
 */
export function emptyFeedAnnouncement(copy: FeedEmptyCopy): string {
  return [copy.title, copy.hint]
    .map(part => part.trim())
    .filter(Boolean)
    .join(' ');
}
```

### Step 3 — the implementation

Create `src/lib/jokeStatus.ts`:

```ts
/**
 * What the joke page's status region says once a load has settled.
 *
 * The page has three outcomes — a joke, no such joke, a failed request — and
 * two of them render a block that a screen reader is never told about. A region
 * that mounts with its message does not announce (round 6), so the page mounts
 * this one empty and fills it from an effect; this module decides the text.
 *
 * The copy is exported as constants because the not-found branch renders the
 * same two strings visibly. One source, so the region and the screen cannot
 * drift apart — the rule `/jokes` follows with its empty state.
 *
 * Strings only: `src/lib/` is outside Tailwind's content globs
 * (`tailwind.config.ts`), so nothing here may return a class name.
 */

/** The headline of the joke-not-found empty state. */
export const JOKE_NOT_FOUND_TITLE = "We couldn't find that joke.";

/** Its second line. */
export const JOKE_NOT_FOUND_HINT = 'It may have been deleted, or the link may be wrong.';

export interface JokeLoadResult {
  /** The message from a failed load, or null/undefined when the request worked. */
  error?: string | null;
  /** Whether a joke came back. */
  found: boolean;
}

/**
 * The announcement for a settled load, or `''` when the joke is there.
 *
 * A failure outranks a missing joke: "we could not reach the server" is
 * actionable and "there is no such joke" is not, and the page renders the error
 * branch first for the same reason. `''` for a loaded joke, because the page
 * then has an h1 with the joke in it and Next's route announcer has already
 * spoken the title — announcing "joke loaded" on top of that is noise.
 */
export function describeJokeLoadResult({ error, found }: JokeLoadResult): string {
  const reason = error?.trim();
  // Any terminal punctuation is replaced, not just a period: a message ending
  // in '!' would otherwise be announced as "Failed!.". Same rule as the feed's
  // error copy in `feedEmptyState.ts`.
  if (reason) return reason.replace(/[.!?]?$/, '.');
  if (!found) return `${JOKE_NOT_FOUND_TITLE} ${JOKE_NOT_FOUND_HINT}`;
  return '';
}
```

Note the quoting: the title is a **double-quoted** string holding a **straight** apostrophe, which
is byte-for-byte what `src/app/joke/[jokeId]/page.tsx:332` renders today and what
`feedEmptyState.ts:39` uses for the same word. Do not "upgrade" it to a typographic apostrophe —
the round-7 convention covers the ellipsis character, not apostrophes, and changing it here would
change a visible string this task is supposed to leave alone.

# Task 11 — the copied label resets from the last press and cleans up

**Objective.** Round 7 recorded it: `CopyLinkButton`'s two-second timer has no cleanup and no
reset. Two consequences, both real:

* **Press twice inside the window** and the second press inherits the first press's deadline. Copy
  at t=0, copy again at t=1.9s, and the label reverts 100ms later — while the toast says the copy
  just happened. The feedback contradicts itself.
* **Navigate away inside the window** and the timer still fires, calling `setJustCopied` on an
  unmounted component. React 18 makes that a silent no-op rather than the old warning, so it costs
  nothing today; it is a leak that becomes a bug the moment the callback does anything else.

There is also a third case round 7 did not name: a copy that *fails* after one that succeeded
leaves the label reading "Copied" underneath a toast saying it could not copy.

**Files**

* modify `src/components/joke/CopyLinkButton.tsx` (lines 3, 23-43)

**No test.** The logic is a timer handle in a ref; there is nothing to extract into `src/lib/`
that would not be a re-implementation of `setTimeout`, and this repo has no React Testing Library.
Verified by typecheck, lint and a 20-second manual check.

### Step 1 — the implementation

Replace lines 1-43 of `src/components/joke/CopyLinkButton.tsx` (down to the closing brace of
`handleCopy`) with:

```tsx
"use client";

import { useEffect, useRef, useState } from 'react';
import { Check, Link2 } from 'lucide-react';

import { Button } from '@/components/ui/button';
import { useToast } from '@/hooks/use-toast';
import { copyToClipboard, jokeShareUrl } from '@/lib/share';

interface CopyLinkButtonProps {
  jokeId: string;
}

/** How long the label stays flipped after a successful copy. */
const COPIED_LABEL_MS = 2000;

/**
 * Copies a clean link to this joke. Not owner-gated: sharing is the point of a
 * joke, and every joke in this app is publicly readable (`firestore.rules`).
 *
 * The label flips to "Copied" for two seconds *and* a toast fires. That is not
 * redundant — the label is the feedback for the person looking at the button,
 * and the toast is the one that gets announced. `aria-live` on the label itself
 * would announce it mid-word as React swaps the text.
 *
 * There is no `document.execCommand` fallback for an insecure origin. The
 * destructive toast points at the address bar, which is honest and always true,
 * and the command it would call is deprecated.
 */
export default function CopyLinkButton({ jokeId }: CopyLinkButtonProps) {
  const { toast } = useToast();
  const [justCopied, setJustCopied] = useState(false);
  // The pending label reset. Held in a ref rather than in state because nothing
  // renders from it, and because the cleanup below has to see the latest handle
  // without re-running.
  const resetTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(
    () => () => {
      if (resetTimerRef.current !== null) clearTimeout(resetTimerRef.current);
    },
    []
  );

  const handleCopy = async () => {
    const url = jokeShareUrl(window.location.origin, jokeId);
    const copied = await copyToClipboard(url, navigator.clipboard);

    // Cancel a reset still pending from an earlier press before deciding what
    // this one means. Without it, a second press inside the window inherits the
    // first press's deadline and the label reverts moments after a copy that
    // just succeeded; and a copy that fails after one that worked leaves the
    // label claiming otherwise.
    if (resetTimerRef.current !== null) clearTimeout(resetTimerRef.current);
    resetTimerRef.current = null;

    if (copied) {
      setJustCopied(true);
      resetTimerRef.current = setTimeout(() => {
        resetTimerRef.current = null;
        setJustCopied(false);
      }, COPIED_LABEL_MS);
      toast({ title: 'Link copied', description: 'Paste it anywhere to share this joke.' });
      return;
    }

    setJustCopied(false);
    // The URL is in the address bar, so there is always a way out — say so
    // rather than just reporting a failure.
    toast({
      title: "Couldn't copy",
      description: 'Copy the address from your browser bar instead.',
      variant: 'destructive',
    });
  };
```

Everything from `  return (` onwards is unchanged.

# Deferrals

Consciously left out of round 8, with the reason.

* **A per-joke `<title>` and per-joke Open Graph card on `/joke/[jokeId]`.** Fourth round this has
  been deferred (rounds 6 and 7 both named it). Task 2 gives every route the *site* card, which is
  the difference between a bare URL and a recognisable link — but a card carrying the joke's own
  text needs `generateMetadata` reading Firestore through the Admin SDK on a route that is
  currently client-fetched only. That is a data-layer change: a server read, a caching decision,
  and a choice about what a joke's card should say (the setup is the interesting half and the
  punchline is the half you must not spoil). It deserves its own round, not a corner of this one.

* **A purpose-built Open Graph image.** Task 2 points at `/logo.png`, a 1395×312 wordmark that a
  card slot will letterbox. A 1200×630 image is a design asset, and inventing one in a code round
  produces the kind of stretched-logo card this task exists to improve on.

* **`loading.tsx` per route.** Every page here is a client component that fetches in an effect and
  already renders `PageLoading` while it does. A route-level `loading.tsx` would paint a *second*
  spinner for the segment's own payload and then swap it for the page's, which is a flash, not
  feedback. Worth revisiting only if any of these routes ever fetch on the server.

* **Per-joke entries in the sitemap.** Same blocker as the per-joke title: an Admin SDK read at
  build time, plus a list that goes stale the moment somebody adds a joke. `/jokes` links to every
  joke, so a crawler reaches them all one hop from a sitemap entry that is already there.

* **Repositioning the dialog for the on-screen keyboard.** Round 7 deferred it and the reason
  holds: following the *visual* viewport as a keyboard opens needs a `window.visualViewport`
  resize listener and a positioning override on a Radix-owned element. Task 14 fixes the short
  *layout* viewport, which is the case that produced an unreachable button.

* **A `document.execCommand` clipboard fallback for insecure origins.** Round 7 recommended
  against it and Task 11 keeps that: the destructive toast points at the address bar, which is
  always true, and the API it would call is deprecated.

* **`focus:ring-2` on `badge.tsx` and on the skip link.** Named in Task 15 and left alone on
  purpose: badges here are never focusable (the chip × is its own button and already correct), and
  a skip link is never clicked, so it has no mouse-focus case to suppress. Round 4 documented the
  second one in the file.

* **Content Security Policy and other security headers in `next.config.ts`.** Real and absent, but
  a CSP for an app loading Firebase Auth, Firestore's streaming transport and Google Fonts is a
  round of its own with a real chance of breaking auth in production — and it cannot be validated
  from this environment. Task 8 leaves `next.config.ts` as a clean empty object, which is a good
  place to start that round.

* **Renaming `/manage` to `/import`.** Fourth round. The nav label, the page title and the filler
  card were all fixed in round 5; the rename is a redirect plus every inbound link for no
  additional user-visible gain.

* **Removing `framer-motion` from `src/app/add-joke/page.tsx`.** Sixth round running, and this
  round adds no new argument. Round 7 tried to measure the bundle cost and could not: Next 16 with
  Turbopack prints no per-route size table.

* **Optimistic updates, and an unsaved-changes guard on the edit form.** Rounds 5, 6 and 7 all
  deferred both; nothing in this round's audit changes the reasoning.

* **Live regions for the home teaser and the community-ratings list.** Round 7 deferred these and
  Task 10 does not reopen them: both resolve once per page load, where Next's route-title announcer
  already reports the navigation. `/joke/{id}`'s not-found branch is different because it is the
  destination of a shared link to a joke that no longer exists, which is a path round 7's Task 7
  created.

* **`src/app/favicon.ico`.** Round 7 reviewed it and decided to keep it: Next serves it at
  `/favicon.ico` for browsers that do not take an SVG icon. Unchanged, and re-recorded here so
  round 9 does not re-audit it.

* **The dangling `aria-describedby` in `src/components/ui/form.tsx`.** Round 6's deferral stands
  verbatim — an unresolvable idref is ignored per accname, and fixing it properly needs a two-pass
  registration in `FormItem` for zero user-facing gain.

* **`.rounded-lg` as the page-break hook in the print block.** Task 16 keeps a page break from
  splitting a joke card by naming the border-radius utility every card happens to carry. It works
  today and it is the wrong kind of selector: it targets a presentational class, so it catches
  anything else rounded the same way (the dialog panel, a rounded image) and, worse, it silently
  stops protecting a card the day somebody changes that card's corner radius. The honest fix is a
  semantic hook the card owns — a data attribute on `JokeListItem`, or a print-specific class
  applied at the card's call sites — which means touching every surface that renders a joke card.
  Recorded rather than done because the selector is not wrong *now*, and swapping it is a
  mechanical change across several components that deserves its own task with its own print check.

* **`CommandDialog`'s panel classes no longer reach the scrolling element.** Task 14 moved the
  scroll from `DialogContent`'s panel onto an inner wrapper. `src/components/ui/command.tsx` passes
  a hidden-overflow and zero-padding class pair into `DialogContent`, expecting to land on the
  element that scrolls; those now land on the panel, and the wrapper inside keeps its own padding
  and its own scroll. Nothing is broken, because `CommandDialog` is exported and never instantiated
  anywhere in the app — the round-8 dependency pass kept `command.tsx` on the strength of its
  export alone. Two ways out and neither belongs in a review errata: delete the component as dead
  code, or give `DialogContent` a second class slot for the wrapper. Whoever instantiates a command
  palette will hit this first, which is the right moment to decide.

* **The dialog's scrollbar sits 24 pixels inside the panel edge.** A consequence of the same Task 14
  move: the panel carries the padding and the wrapper scrolls, so the scrollbar is drawn at the
  wrapper's edge rather than the panel's, and on a short viewport it appears floating a padding's
  width in from the border. It is cosmetic and it only shows while there is something to scroll.
  Fixing it means moving the horizontal padding off the panel and onto the wrapper's children,
  which redistributes the padding that Task 14 was careful not to disturb — the header, body and
  footer would each have to carry it, and the panel's border-to-content spacing would then depend
  on three call sites agreeing instead of one.
