**Goal:** Fix what six rounds of structure, motion, visuals, flows and accessibility never looked at — **the content itself, and the app at 200 jokes.** A joke written with its punchline on its own line is rendered as one paragraph on every surface in the app. One long joke stretches three neighbouring cards with it. ## Audit — what this round fixes

Severity is user impact, not effort.

### A. Content display — the biggest cluster, and the one nobody has looked at

- **A1 — Every surface collapses a joke's line breaks.** `joke-list-item.tsx:71` (`<p>{joke.text}</p>`), `JokeHeader.tsx:28-30` (the detail `h1`) and `add-joke/page.tsx:347` (the AI variation cards) render joke text with default `white-space`. The add and edit forms are `<Textarea>`s, so a user *can* and does write

  > Why did the scarecrow win an award?
  >
  > He was outstanding in his field.

  and gets it back as one run-on line, everywhere, forever. `ExplanationCard.tsx:68` and `CommunityRatings.tsx:68` both carry `whitespace-pre-wrap` — the AI's prose and other people's comments keep their shape; only the jokes do not.
- **A2 — One long joke sets the height of its whole grid row.** The feed is a CSS grid (`joke-list.tsx:74`), so cards stretch to the tallest in the row. There is no `line-clamp` anywhere on `joke.text`. A 400-word bit leaves three neighbours as mostly whitespace, at every breakpoint. There is also no `break-words`, so a URL or hashtag with no spaces in it runs past the card's content box.
- **A3 — A long category name is clipped mid-word with no ellipsis.** `joke-list-item.tsx:72-77` positions the badge `absolute bottom-0 left-0` inside the card, and the `Card` is `overflow-hidden` (`:43`). "Observational comedy about airports" becomes "Observational comedy about airp". The `pb-8` on the text (`:71`) exists only to reserve room for that absolute box. The badge is also `text-[11px]` — **the only arbitrary font size left in the app** (`grep -rn 'text-\[' src/` returns exactly one hit), i.e. the fifth type scale round 4 set out to delete.
- **A4 — The "used" tint is invisible in both themes.** `joke-list-item.tsx:65` tints an owner's used card `bg-muted/30`. Computed sRGB relative luminance: light `--muted` 96.1% at 30% over a white card composites to 98.83%, **1.03:1** against the card. Dark `--muted` 20% at 30% over a 16% card composites to 17.2%, **1.04:1**. So the feed-level signal for the flag that the entire `usageStatus` filter exists to track does not exist. (It is also the one place in the app where a state is signalled by colour alone — round 6's F5 audit missed this card.)
- **A5 — A card's rating number and count are tooltip-only.** `joke-list-item.tsx:93-110` wraps the stars in a `TooltipTrigger asChild` around a non-focusable `<div>`: unreachable by keyboard, unreachable by touch. Round 6 put the count into `StarRating`'s `aria-label`, which fixed the screen-reader case and left every sighted phone user with five small stars and no number. Each card also mounts its own `TooltipProvider` — 12 of them per page, 200 in a fully paged-in collection.
- **A6 — Every community rating is signed "User".** `CommunityRatings.tsx:62-64` renders the literal string `User` with the comment "Replace with user identifier if available". Every comment on every joke is attributed identically, and it reads as unfinished scaffolding rather than as a deliberate choice. There is no display-name field in the data model, so the honest label is the one `JokeHeader.tsx:51` already uses: "A user".

### B. The feed at scale, and what it announces

- **B1 — Three components mount `role="status"` with their message already inside, so none of them announces anything.** `EmptyState.tsx:45`, `PageLoading.tsx:32-33`, and `JokeGridSkeleton` in `jokes/page.tsx:35-40`. This is the exact pattern round 6 identified and fixed for the generation status (`af11636`) and then recorded as a leftover here. Consequence: search for "penguin", get "No jokes matched “penguin”." on screen, and **nothing is announced at all** — the one live region on `/jokes` (`:333`) only ever carries the "load more" append.
- **B2 — Nothing on the page says how many jokes there are.** Not the toolbar, not the footer of the grid. A returning user with 200+ jokes cannot tell whether a filter matched 3 or 130, and the only feedback that the list has ended is the sentence "No more jokes to load for the current filters." — which reports the *absence* of more rather than the *presence* of what they have.
- **B3 — `PAGE_SIZE` is 10 against a 1/2/3/4-column grid** (`jokeService.ts:27`, `joke-list.tsx:74`). Ten never fills the last row at any breakpoint above one column (4+4+2, 3+3+3+1), and 200 jokes costs **20 "Load More" presses**. Twelve divides evenly by 1, 2, 3 and 4.

### C. Filters that cannot do what they say

- **C1 — A comma in a category name silently drops the filter** (recorded deferral, round 3). `jokeFilters.ts:36-42` and `:77-80` round-trip `selectedCategories` through one comma-joined param, so a category called `Dad, jokes` — a name a user will type — parses back as two names, neither of which exists, and both are pruned. The chip disappears and the feed answers a query the user did not ask for.
- **C2 — The "Rating" filter filters a field no screen can write.** `filterFunnyRate` queries `funnyRate` (`jokeService.ts:90-92`). `funnyRate` is written by the CSV import (`funnyrate` column) and by `/api/jokes/add`; the add form does not collect it and the edit form does not either. So for every joke added through the UI it is `0`, and a user filtering "4 Stars" gets an empty feed and the message "No jokes match these filters." The label is worse than the gap: on a card the visible stars are the *community* average, so "Rating: 4 Stars" reads as a filter on the number the user is looking at. It is not.
- **C3 — The dialog offers controls that cannot work.** Signed out (or signed in with no categories yet), the Categories combobox renders permanently disabled reading "Select categories…" with "No categories available." behind it. Usage Status is offered to signed-out visitors, where it filters *other people's* used flags.

### D. Sharing, and the missing micro-interaction

- **D1 — There is no way to send someone a joke.** No copy-link, no share, on the one page whose entire purpose is a single joke. The card is a `<Link>`, so a mouse user can right-click → copy link address; a phone user cannot, and the detail page — where you are when you decide to share — offers nothing but Back.

### E. Mobile, once more

- **E1 — The account button carries the full email address from 640px up.** `navbar.tsx:85`, `sr-only sm:not-sr-only`. At 640–768px the bar is the wordmark + three icon-and-label links + `marco.something@example.com` + the theme toggle. Round 6 correctly stopped `display:none` from eating the accessible name; the visible string is a different problem.
- **E2 — Dialogs cannot scroll.** `dialog.tsx:49` and `alert-dialog.tsx:49` are `fixed top-[50%] translate-y-[-50%] grid` with **no `max-height` and no `overflow`**. The filter dialog runs ~430px tall; in landscape on a phone, or on a short viewport, its footer — the Apply button — is off-screen and unreachable, because there is nothing to scroll.
- **E3 — Toolbar wrap at 375px is correct.** Re-verified after round 4's Task 16: search takes its own row (`basis-full`), the scope toggle and Filters share the next, chips take a row (`empty:hidden` when there are none), and the action cluster is `w-full`. **No fix.** Recorded so the next round does not re-audit it.

### F. Delay with no cause

- **F1 — "Add a joke" is a full-page spinner until an unrelated subscription lands.** `add-joke/page.tsx:169-171` gates the entire page on `loadingCategories`, and `add-joke-form.tsx:105` folds `loadingCategories` into `isFormDisabled`, which disables the **joke text field**. A user with 80 categories on a slow connection cannot start typing their joke because a combobox is loading. `CategoryCombobox` already disables itself on `loadingCategories` (`:90`), so the gate is doing the same job twice, one layer too high.

### G. Weight on every page

- **G1 — The favicon is the 209KB wordmark.** `layout.tsx:32-34` sets `icons: { icon: '/logo.png' }`. Browsers fetch that path directly — it does not go through the image optimizer — so **209KB of PNG on every page load**, to render a 1395×312 wordmark into a 16px square where it is an illegible sliver.
- **G2 — A whole webfont family for one number.** `Geist_Mono` is loaded in the root layout (`layout.tsx:17-20`, `:45`) and `font-mono` appears exactly once in the app: the temperature readout on `/add-joke` (`:249`).
- **G3 — `next/image` usage is otherwise correct.** One image in the app (`logo.tsx`), fixed width, `priority` on the nav instance only. The `remotePatterns` entry for `picsum.photos` in `next.config.ts` is dead but harmless. **No fix.**

### H. System hygiene with user-facing consequences

- **H1 — `CardTitle`'s default is `text-2xl`, and the documented card-title scale is `text-lg`.** `card.tsx:53`. All **eleven** call sites pass `className="text-lg"` to correct it (`grep -rn CardTitle src/`), so the next card added to the app gets the wrong size by default and the type scale documented in `globals.css:152` is a thing every author must remember rather than a thing the component does.
- **H2 — `CardTitle`'s ref typing is unsound** (recorded leftover). It is `forwardRef<HTMLHeadingElement>` while rendering a `div` by default, and `as` is widened to `ElementType` to get past the union. No user-facing effect on its own — folded into H1's commit because it is the same six lines.
- **H3 — The toast sensitivity rule is not where the next author will look** (recorded leftover). "Destructive → assertive, everything else → polite" lives in `Toaster` and in `PROJECT_PROGRESS.md`, not in the conventions block at `use-toast.ts:11-26` that carries every other toast rule.
- **H4 — A five-word toast title against a three-word convention** (recorded leftover). `csvReport.ts:50`, `Import finished with skipped rows`, with the exception written into the JSDoc above it (`:33`).
- **H5 — A failed CSV write fires two destructive toasts and throws away the useful one** (recorded leftover). `handleApiCall` toasts "Something went wrong" (`JokeContext.tsx:258`), then `csv-import.tsx:161-167` toasts "Couldn't import that file" with the same message; `TOAST_LIMIT` is 1, so the second evicts the first. The survivor blames the *file* for what may be a permission or network failure, and `setStatusMessage('')` on the next line wipes the page's report — including `jokeService.importJokes`'s partial count (`jokeService.ts:271-273`, "Imported 40 of 120 jokes before the import failed"), which is the single most useful fact in the whole flow and exists nowhere else.

### Deliberately deferred (documented in Task 16, not implemented)

- **Removing `framer-motion` from `add-joke/page.tsx`** — fifth round. The brief allowed it back in scope only on a *concrete* user-facing problem. The candidate problem is bundle weight on the route where you type a joke, and **this audit could not measure it**: Next 16 with Turbopack prints no per-route size table (`npx next build`, verified). An unmeasured suspicion is not a concrete problem. It stays where it is.
- **Renaming `/manage` to `/import`** — third round. The nav label, the page title and the filler card were all fixed in round 5; the route rename is a redirect plus every inbound link for no additional user-visible gain.
- **Optimistic updates for rate / toggle / delete** — the pessimistic writes are correct and round 5's Task 15 made their failures legible. Unchanged reasoning.
- **An "unsaved changes" guard on the edit form** — still needs route-change interception the App Router does not offer cleanly, and round 5's Task 8 removed the case that actually lost data.
- **A per-joke `<title>` on `/joke/[jokeId]`** — round 6's deferral stands: it needs `generateMetadata` reading Firestore through the Admin SDK on a client-fetched route. Task 7 gives that page a shareable link, which is the user-facing half of the same want.
- **Repositioning dialogs for the on-screen keyboard.** Task 10 fixes the short-viewport case with `dvh` + scroll. Following the *visual* viewport as the keyboard opens needs a `window.visualViewport` resize listener and a positioning override on a Radix-owned element — a new mechanism, not a polish fix. - **Display names for raters.** Task 4 changes "User" to "A user", which is honest. Real attribution needs a profile field, an auth-flow change and a privacy decision about publishing anyone's identity next to their opinion of a joke.
- **A `funnyRate` field on the *add* form.** Task 15 adds it where it belongs — you rate your own material after living with it, not in the same keystroke as writing it. The add form stays three fields.

### Task 2: `CardTitle` defaults to the documented card scale

**Objective:** Closes **H1** and **H2**.

The type scale in `globals.css:152` says a card title is `text-lg font-semibold`. The component says `text-2xl`, and all eleven call sites correct it by hand. The next card in the app will get `text-2xl`, and the review that catches it will be a person rather than the component. Same commit closes the unsound ref typing, because it is the same six lines.

**Files:**
- Modify: `src/components/ui/card.tsx`, `src/app/add-joke/page.tsx`, `src/app/edit-joke/[jokeId]/page.tsx`, `src/app/joke/[jokeId]/page.tsx`, `src/components/joke/ExplanationCard.tsx`, `src/components/joke/RatingForm.tsx`, `src/components/joke/CommunityRatings.tsx`, `src/components/csv-import.tsx`

**Steps:**

1. Replace `CardTitle` in `src/components/ui/card.tsx` (`:32-61`) with:

```tsx
type CardTitleTag = 'div' | 'h1' | 'h2' | 'h3';

interface CardTitleProps extends React.HTMLAttributes<HTMLElement> {
  /**
   * Element to render. `div` — shadcn's original — is right for a card whose
   * title is not a section of the page. Pass `h1`/`h2`/`h3` when the card *is*
   * a section: with everything a div, `/joke/[jokeId]` and `/add-joke` had one
   * heading each and no outline for a screen reader to navigate.
   */
  as?: CardTitleTag;
}

const CardTitle = React.forwardRef<HTMLElement, CardTitleProps>(
  ({ className, as = 'div', ...props }, ref) => {
    // `ElementType` rather than the union directly: a union of intrinsic tags in
    // JSX position makes TypeScript resolve the ref against every member at once
    // (HTMLDivElement *and* HTMLHeadingElement), which no single ref satisfies.
    // The ref is typed `HTMLElement` — the one type that is honest for all four
    // tags — instead of `HTMLHeadingElement`, which was a lie for the default.
    const Comp = as as React.ElementType;

    return (
      <Comp
        ref={ref}
        // The documented card-title step (globals.css). It used to be `text-2xl`
        // and every one of the eleven call sites passed `text-lg` to undo it, so
        // the scale lived in the call sites and the component fought them.
        className={cn(
          "text-lg font-semibold leading-none tracking-tight",
          className
        )}
        {...props}
      />
    )
  }
)
CardTitle.displayName = "CardTitle"
```

/**
 * Building and copying a shareable link to a joke.
 *
 * The URL construction and the clipboard call are both here rather than in the
 * component, because both have edge cases worth pinning: an origin with a
 * trailing slash would produce `//joke/x`, and `navigator.clipboard` is absent
 * on an insecure origin and rejects when the document is not focused — a failed
 * copy must be reported, not silently swallowed.
 *
 * Strings and booleans only: `src/lib/` is outside Tailwind's content globs
 * (`tailwind.config.ts`), so nothing here may return a class name.
 */

/** The part of `navigator.clipboard` this module uses, so tests can inject one. */
export interface ClipboardLike {
  writeText(text: string): Promise<void>;
}

/**
 * The canonical public URL for a joke. Built from the origin and the id rather
 * than from `location.href`, so a link copied off a filtered or otherwise
 * decorated URL is still the clean one.
 */
export function jokeShareUrl(origin: string, jokeId: string): string {
  return `${origin.replace(/\/+$/, '')}/joke/${encodeURIComponent(jokeId)}`;
}

/**
 * Copies `text`, reporting success as a boolean rather than throwing: the caller
 * shows a toast either way and has nothing useful to do with the rejection
 * value. `false` also covers "there is no clipboard here at all", which is the
 * case on an insecure origin.
 */
export async function copyToClipboard(text: string, clipboard?: ClipboardLike): Promise<boolean> {
  if (!clipboard) return false;
  try {
    await clipboard.writeText(text);
    return true;
  } catch {
    return false;
  }
}
```

/** One reading of the feed, as the page's status region reports it. */
export interface FeedSnapshot {
  /** The serialized filter set these results answer (`filtersToSearchParams`). */
  key: string;
  /** How many jokes are on the page, or `null` while a fetch is in flight. */
  count: number | null;
}

/**
 * The text of the feed's status region for the transition `previous` → `next`.
 *
 * One region, four things to say, in priority order: a fetch is running; the
 * result is empty (in which case the region says exactly what the empty state
 * on screen says, so the two cannot contradict each other); a page was appended
 * (delegated to `describeFeedAppend`, which knows that a filter change also
 * changes the count and is not an append); or this is a result set, with its
 * size.
 *
 * Never returns `''`. The region is mounted permanently and only announces when
 * its text *changes*, so a blank string would be a wasted state — and the size
 * of a result set is precisely the fact the feed has never reported.
 */
export function describeFeedStatus(
  previous: FeedSnapshot | null,
  next: FeedSnapshot,
  emptyTitle: string
): string {
  if (next.count === null) return 'Loading jokes…';
  if (next.count === 0) return emptyTitle;

  const append =
    previous && previous.count !== null
      ? describeFeedAppend(
          { key: previous.key, count: previous.count },
          { key: next.key, count: next.count }
        )
      : '';

  return append || `${next.count} joke${next.count === 1 ? '' : 's'} shown.`;
}
```
