## UX audit — what this round fixes

### A. Flows

- **A1 — A failed save silently deletes what you typed.** `handleAddJokeAndRedirect` (`src/app/add-joke/page.tsx:127-139`) catches the error from `addJoke` and does **not** re-throw. `AddJokeForm.onSubmit` (`src/components/add-joke-form.tsx:82-83`) therefore sees a resolved promise and runs `form.reset()`. On a permission error or a dropped connection the user gets a red toast *and* an empty form. The joke — possibly AI-generated and then edited — is gone.
- **A2 — Two of the three save-error paths are completely silent.** `handleApiCall` (`src/contexts/JokeContext.tsx:228`) deliberately suppresses errors whose message contains `Category name cannot be empty` or `permission denied`, with the comment "the callers surface them in context". No caller does. `AddJokeForm`'s catch only calls `console.error`; the edit page's catch (`src/app/edit-joke/[jokeId]/page.tsx:129-131`) re-implements the same suppression. A category failure produces **no** user-visible output anywhere.
- **A3 — The delete confirmation closes before the delete runs.** `AlertDialogAction` closes the dialog on click by default (`src/app/edit-joke/[jokeId]/page.tsx:282-289`). The `isDeleting` state and its `Deleting…` label are unreachable — the dialog is already unmounted. On failure the user is dropped back onto an unchanged form with a toast, with no indication of which action failed.
- **A4 — Four actions fire two toasts each.** `handleApiCall` toasts on success, and then the calling page toasts again: add (`add-joke/page.tsx:134`), update and delete (`edit-joke/[jokeId]/page.tsx:125,145`), rate (`joke/[jokeId]/page.tsx:232`). `TOAST_LIMIT` is 1 (`src/hooks/use-toast.ts:11`), so the second immediately evicts the first — the user sees a flicker and the *generic* message loses to the specific one at random points in the code. The error paths double up the same way.
- **A5 — Dead validation branches.** `RatingForm`'s submit button is disabled while `ratingInputValue === 0` (`RatingForm.tsx:80`), so the "Please select a star rating (1-5)" toast (`joke/[jokeId]/page.tsx:225-228`) can never fire. On the auth page, `required` and `minLength={6}` on the inputs make the browser block submit, so both "Validation Error" toasts (`auth/page.tsx:34-41`) are unreachable too — meaning the messages that were written for the user are never shown to the user.

### B. Interaction gaps

- **B1 — A failed feed fetch renders as an empty feed.** `fetchJokesInternal`'s catch sets `jokes` to `[]` (`JokeContext.tsx:172`). `/jokes` then shows "No jokes found. Try adding some or adjusting your filters!" — the app blames the user's filters for a network error, and offers no retry.
- **B2 — Empty states have no way out.** Round 4 deliberately shipped `EmptyState` as icon + copy only, because a CTA would have been a behaviour change. Behaviour changes are in scope now: "No jokes matched *x*" with four filters active should offer to clear them.
- **B3 — Active-filter badges are read-only.** `jokes/page.tsx:156-175` renders up to six badges and the only way to drop one is "Clear All", which drops all of them. Removing one category means reopening the dialog, finding it in a popover and unticking it.
- **B4 — Focus returns to the wrong control.** The magnifier button (`JokeFilterDialog.tsx:113-121`) opens the dialog but is *not* a `DialogTrigger`, so Radix restores focus to the Filters button on close. The same opener leans on `setTimeout(…, 100)` to focus the search input — a race against the mount, not a guarantee.
- **B5 — The toast close button is invisible on touch.** `ToastClose` is `opacity-0 … group-hover:opacity-100` (`ui/toast.tsx:80`). There is no hover on a phone, so the only way to dismiss a toast is a swipe nobody is told about.
- **B6 — Touch targets below the floor.** The filter-dialog chip remove button is a 12px icon in a button with no padding (`JokeFilterDialog.tsx:252-259`); interactive stars are `p-0 h-auto w-auto` (`StarRating.tsx:118`); "Clear All" is `p-2 h-auto` and the detail-page Edit button is `px-2 h-auto py-1`. WCAG 2.5.8 sets 24×24px as the floor.
- **B7 — iOS zooms the add-joke form on focus.** `Input` and `Textarea` are `text-base md:text-sm` precisely so mobile keeps 16px, and `add-joke-form.tsx:119,136,150` overrides that back to `text-sm`. Safari zooms the viewport on any input under 16px.

### C. Information architecture

- **C1 — Search is inside a modal.** The only way to search is: click a magnifier → a dialog opens → type → Enter. There is no search field on the page. Search is the primary discovery mechanism for a joke collection and it is two interactions and one occluding surface deep.
- **C2 — "My jokes" is buried.** Scope is a `<Select>` inside the same dialog. It is the single most-used filter for a signed-in user (it is the difference between "the app" and "my collection"), and the home page has a whole button for it while `/jokes` hides it.
- **C3 — "Back to All Jokes" discards your filters.** `router.push('/jokes')` from the detail page (`joke/[jokeId]/page.tsx:306,329,346`). Arrive from `/jokes?scope=user&categories=Puns`, open a joke, come back — you are on the unfiltered public feed and your scroll position is gone.
- **C4 — `/manage` is a CSV importer called "Manage", padded with a card that explains what the page is.** The nav label promises settings; the page is one file input. The "About This Page" card (`manage/page.tsx:62-72`) exists because the page looked empty.

### D. Microcopy

- **D1 — Nine ways to say "loading".** "Loading jokes...", "Loading joke...", "Loading page...", "Loading data...", "Loading necessary data...", "Loading your categories...", "Verifying authentication...", "Verifying...", "Checking authentication..." — each with its own hand-rolled centred-spinner block, three of which use `flex-col`/`mt-2` and four `ml-2`.
- **D2 — Toast titles have no rule.** `Success` / `Success!` / `Error` / `AI Error` / `Update Error` / `Delete Error` / `Rating Submission Error` / `Validation Error` / `Login Required` / `Authentication Required` / `Access Denied` / `Import Information` / `No Changes` / `Jokes Generated!` / `Inspiration Loaded!`. Title Case and Sentence case, with and without exclamation marks, naming the failed component instead of the failed action.
- **D3 — `...` and `…` are both used**, sometimes in the same file.

### E. Round-4 deferrals (all six, folded in)

- **E1** Auth `CardTitle` is `text-2xl` against a documented `text-lg` card title → Task 2.
- **E2** `add-joke-form.tsx` runs its own `text-xs` label scale → Task 1.
- **E3** `RatingForm` / `CommunityRatings` / `ExplanationCard` card titles are `text-xl` → Task 1.
- **E4** The auth page keeps a sixth page container → Task 2.
- **E5** The joke-not-found card has no icon and no shape → Task 3.
- **E6** Dark-mode card/page separation is ≈1.09:1 → Task 4.

### Deliberately deferred (documented in Task 18, not implemented)

- Renaming the `/manage` route to `/import`. Task 17 fixes the label, the title and the filler; moving the route means a redirect and every inbound link, for no additional user-visible gain.
- Removing `framer-motion` from `add-joke/page.tsx`. Third round in a row this is out of scope, and it still is.
- Optimistic updates for rate/toggle/delete. The current pessimistic writes are *correct* — nothing paints until the write lands, and Task 15 makes failures legible. Optimism here buys a few hundred milliseconds and costs a rollback path per action.

```tsx
import type { FC } from 'react';
import { Loader2 } from 'lucide-react';

import { cn } from '@/lib/utils';

interface PageLoadingProps {
  /**
   * What is loading, as a sentence fragment ending in an ellipsis character:
   * "Loading jokes…", "Checking your sign-in…". Always name the thing — a bare
   * "Loading…" tells the user nothing they can't see from the spinner.
   */

  /** Drop the page container and the viewport centring, for a loader that sits
   *  inside a section that already has both. */

  className?: string;
}

/**
 * The app's one loading block. Every page had its own: four used `flex-col`
 * with `mt-2`, four a row with `ml-2`, and the labels ran to nine phrasings of
 * the same idea.
 *
 * `animate-spin` deliberately keeps turning under `prefers-reduced-motion` —
 * see the policy block at the end of `globals.css`. A frozen spinner reads as
 * a hung request.
 */
const PageLoading: FC<PageLoadingProps> = ({ label, inline = false, className }) => (
  // `role="status"` with the label as its only content: the announcement is
  // the label, and it fires when this mounts and again when it unmounts to
  // whatever replaced it.
  <div
    role="status"
    className={cn(
      'flex items-center justify-center gap-2',
      inline
        ? 'min-h-[150px]'
        : 'container mx-auto px-4 py-8 sm:px-6 md:py-12 min-h-[calc(100vh-8rem)]',
      className
    )}
  >
    <Loader2 className="h-8 w-8 animate-spin text-primary" aria-hidden="true" />
    <p className="text-muted-foreground">{label}</p>
  </div>
);

export default PageLoading;
```

```ts
    // the service ANDs the remaining tokens client-side and can hand back an
    // empty page while later pages still hold matches (it pages on, but gives
```

```ts
/**
 * Remembers which joke feed the user came from, so the detail page's back
 * button returns to it with its filters intact instead of dumping them on the
 * unfiltered public feed.
 *
 * `sessionStorage` rather than history introspection: the App Router does not
 * expose "did this navigation start inside the app", and `router.back()` on a
 * deep link from a search engine leaves the site entirely. A remembered URL is
 * a value we wrote ourselves, so it can be validated.
 *
 * The storage object is a parameter so this is testable without a DOM and so
 * the caller decides between session and local storage.
 */
export const FEED_PATH = '/jokes';

const STORAGE_KEY = 'jokehub:last-feed-url';

/** The slice of the Storage interface this module uses. */
export interface StorageLike {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}

/**
 * A same-origin path on the feed, and nothing else. The value round-trips
 * through storage, where anything could have put it, so a protocol-relative
 * URL (`//evil.example`) or a path to another route is rejected rather than
 * handed to <Link>.
 */
function isFeedUrl(url: string): boolean {
  return url === FEED_PATH || url.startsWith(`${FEED_PATH}?`);
}

export function rememberFeedUrl(storage: StorageLike | undefined, url: string): void {
  if (!storage || !isFeedUrl(url)) return;
  try {
    storage.setItem(STORAGE_KEY, url);
  } catch {
    // Safari private mode and quota failures: the back button falls back to
    // the plain feed, which is where it went before this existed.
  }
}

export function readFeedUrl(storage: StorageLike | undefined): string {
  if (!storage) return FEED_PATH;
  try {
    const stored = storage.getItem(STORAGE_KEY);
    return stored && isFeedUrl(stored) ? stored : FEED_PATH;
  } catch {
    return FEED_PATH;
  }
}
```

```tsx
    e.preventDefault();

    const nextErrors: { email?: string; password?: string } = {};
    if (!email.trim()) nextErrors.email = 'Enter your email address.';
    if (!password) nextErrors.password = 'Enter your password.';
    else if (password.length < 6) nextErrors.password = 'Passwords are at least 6 characters.';
    if (nextErrors.email || nextErrors.password) {
      setErrors(nextErrors);
      return;
    }

    setErrors({});
    setIsLoading(true);
    try {
      if (isLogin) {
        await signIn(email, password);
      } else {
        await signUp(email, password);
      }
      toast({

        description: isLogin ? 'Taking you back…' : 'Welcome to Joke Hub.',

    // eslint-disable-next-line @typescript-eslint/no-explicit-any -- Firebase auth errors expose a dynamic `code` field not present on Error.
    } catch (error: any) {
      console.error('Auth error:', error);
      let errorMessage = error.message || (isLogin ? 'Failed to login.' : 'Failed to sign up.');
      if (error.code === 'auth/invalid-credential' || error.code === 'auth/user-not-found' || error.code === 'auth/wrong-password') {
```
