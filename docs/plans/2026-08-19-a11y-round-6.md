## A11y audit — what this round fixes

Severity is user impact, not effort. WCAG references are to 2.2 success criteria.

### A. Landmarks and page structure

- **A1 — No skip link (2.4.1, Level A).** `layout.tsx` renders `<Navbar/>` then `<main>`. A keyboard user tabs the logo, up to three nav links, the account menu and the theme toggle on **every** page load and every route change before reaching content. `<main>` exists but has no `id` and no `tabIndex`, so there is nothing to skip *to*.
- **A2 — The home page has no `h1` (1.3.1 A, 2.4.6 AA).** `src/app/page.tsx` opens at `<h2>A Taste of Humor</h2>` (`:64`). The wordmark is an `<Image>` in a bare `<header>`. Heading level 1 is skipped entirely.
- **A3 — Card titles are `<div>`s, so five pages have exactly one heading (1.3.1 A).** `CardTitle` (`ui/card.tsx:32-45`) renders a `div`. Eleven call sites use it. On `/joke/[jokeId]` the outline is `h1` (the joke) and then nothing — "The Comedian's Take", "Rate this Joke" and "Ratings & Comments" are unreachable by heading navigation. On `/add-joke` the outline is `h1` → `h3` ("Choose Your Favorite", `:314`), a skipped level.
- **A4 — `<nav>` has no accessible name** (`navbar.tsx:34,48`). One nav, so this is 1.3.1-adjacent rather than a failure, but the landmark list reads "navigation" with nothing to distinguish it from the search form's landmark.

### B. Names, roles, values

- **B1 — Every nav control loses its name below 640px (4.1.2 A, 2.4.4 A).** `navbar.tsx:72,82,100` hide the label with `hidden sm:inline` (`display:none`, excluded from the accessible name), and lucide-react stamps `aria-hidden="true"` on an icon with no children. On a phone the Home, Jokes and Import links, the account menu and the Login button are **buttons with no accessible name at all**. This is the single worst defect in the app: the primary navigation is unusable with a mobile screen reader.
- **B2 — The toast close button has no name (4.1.2 A).** `ui/toast.tsx:77-88` renders `<ToastClose>` containing only an aria-hidden `<X>`. (Radix wraps `Close` in `ToastAnnounceExclude`, so adding visually hidden text is safe — it does not leak into the toast announcement.)
- **B3 — The interactive star rating never says what the rating is (4.1.2 A, 1.3.1 A).** `StarRating.tsx:106-141` renders five sibling buttons labelled "Set rating to *n* stars" with no group, no role, no checked state, and five tab stops. Nothing announces the current value, and nothing announces that a value was set. The read-only branch (`:86-104`) is correct already.
- **B4 — The temperature slider has no name (4.1.2 A, 3.3.2 AA).** `add-joke/page.tsx:236-247` labels the slider with `<Label htmlFor="temperature-slider">`, but Radix puts that `id` on the wrapper `<span>`; the element carrying `role="slider"` is the thumb, which has no name. The `<label for>` also points at a non-labelable element.
- **B5 — Tooltip-only information on joke cards (1.1.1 A, 2.1.1 A).** `joke-list-item.tsx:93-109` puts the rating count in a `TooltipContent` whose trigger is a non-focusable `<div>`. `StarRating`'s label carries the average but not the count, so keyboard and screen-reader users never learn how many ratings a joke has.

### C. Announcements (dynamic content)

- **C1 — "Load More" appends ten cards in complete silence (4.1.3 AA).** `jokes/page.tsx:265-273`. Focus stays on the button, the DOM grows above it, and nothing is announced. The single highest-traffic dynamic update in the app.
- **C2 — No route change is ever announced (2.4.2 A, 4.1.3 AA).** Next's App Router *does* ship a route announcer (`next/dist/client/components/app-router-announcer.js`) and it announces `document.title` — **but only when the title changes**. `layout.tsx:21-27` sets one static `title: 'Joke Hub'` and no page overrides it, so the string never changes and the announcer never fires. Seven routes, one title, zero announcements. This is also a plain 2.4.2 failure on its own.
- **C3 — Every toast interrupts (4.1.3 AA, quality).** Radix defaults `Toast` to `type="foreground"` → `aria-live="assertive"` (`react-toast/dist/index.mjs:295,370`). "Joke added" cuts off whatever the screen reader was saying. Assertive is right for a failure the user must act on and wrong for a confirmation.
- **C4 — The CSV import reports nothing until it is over (4.1.3 AA).** `csv-import.tsx:247` renders "Processing your file…" as an inert `<p>`; the result exists only in a toast. A file with 400 rows produces silence, then one assertive interruption.
- **C5 — Long in-flight operations are silent.** The AI generation placeholder (`add-joke/page.tsx:296-306`), the explanation stream (`ExplanationCard.tsx:47-51`) and the in-flight delete (`edit-joke/[jokeId]/page.tsx:305-306`) all render visible "working" text in non-live regions. Round 5 made `isDeleting`/`Deleting…` *reachable*; it is still inaudible.

### D. Focus management

- **D1 — Removing a filter chip throws focus to `<body>` (2.4.3 A).** `jokes/page.tsx:212-222`: the × applies `chip.next`, the URL changes, the chip unmounts, and the user is returned to the top of the document. Removing four chips means four full traversals of the page. "Clear All" (`:236-240`) does the same to itself.
- **D2 — A client-side route change leaves focus where it was (2.4.3 A).** The App Router does not move focus. Combined with **C2** a navigation is completely undetectable: nothing is announced and focus is still on the link, which no longer exists.
- **D3 — Dialog focus return is correct.** Verified after round 5: the magnifier opener is gone and the single opener is a real `DialogTrigger` (`JokeFilterDialog.tsx:104-110`), so Radix restores focus to the Filters button. The `AlertDialog` trigger likewise. No fix needed — recorded so the next round does not re-audit it.
- **D4 — The in-flight delete blocks Escape (`edit-joke/[jokeId]/page.tsx:276`).** Reviewed against 2.1.2: `deleteJoke` always settles, the block is transient and the dialog keeps a full focus cycle, so this is not a keyboard trap. It does need to *say* it is busy (**C5**).

### E. Forms

- **E1 — Root-level form errors are announced by nothing (3.3.1 A, 4.1.3 AA).** `add-joke-form.tsx:166-168` and `edit-joke/[jokeId]/page.tsx:266-268` render `<FormMessage>` outside any `<FormField>`. `useFormField()` then reads an empty context: the element renders with `id="undefined-form-item-message"`, is referenced by no control and carries no `role`. The message the user needs ("You do not have permission to add this joke.") is silent.
- **E2 — Required fields are not marked (3.3.2 AA).** `text` and `category` are required by the zod schema in both forms; only the optional field is marked, by the "(Optional)" in its label.
- **E3 — The comment character counter is not associated (1.3.1 A).** `RatingForm.tsx:78` renders `{n}/1000 characters` as a loose `<p>` next to a `maxLength={1000}` textarea.
- **E4 — Field labels and error wiring are otherwise correct.** `ui/form.tsx` gives every field `aria-invalid` and an `aria-describedby` that includes the message id when there is an error; the auth page was fixed in round 5 (`auth/page.tsx:150-151,170-174`); the CSV file input has a real `<Label htmlFor>`. No fix needed.

### F. Contrast

Computed from the tokens in `globals.css`, sRGB relative luminance, not estimated.

- **F1 — Destructive text fails AA in both themes (1.4.3 AA).** Light `--destructive` `0 84.2% 60.2%` = rgb(239,68,68), L≈0.229 → **3.76:1 on white**, **3.35:1 on `bg-destructive/10`**. Dark `--destructive` `0 62.8% 50.6%` = rgb(208,50,50), L≈0.159 → **2.95:1 on `--card`**. This is every `FormMessage`, every `FormLabel` in its error state, the three error cards, both auth field errors and the auth failure block. The 4.5:1 floor is missed by a wide margin.
- **F2 — The destructive *surface* fails too (1.4.3 AA).** `--destructive-foreground` (98%) on light `--destructive` is **3.76:1** — the "Delete Joke" button label and every destructive toast. Dark is fine (5.02:1).
- **F3 — `text-primary` links inside cards fail in dark mode (1.4.3 AA).** Dark `--primary` `270 60% 65%`, L≈0.249 → **4.22:1 on `--card`** and **4.14:1 on `bg-primary/10`**. That is the "log in or sign up" link in `RatingForm`, and the alert links in `add-joke-form` and `csv-import`. On `--background` it scrapes past at 4.98:1, and `Header`'s `h1` is large text (3:1), so only the in-card links fail.
- **F4 — Everything else clears AA.** `--muted-foreground` 5.74:1 (light, on white) / 5.78:1 (dark, on card) / 5.01:1 (dark, on muted); `--accent-foreground` on `--accent` 5.45:1 light, 5.61:1 dark; focus ring `--ring` against the page 6.45:1 light, 4.98:1 dark (needs 3:1). Round 5's figures re-verified and correct.
- **F5 — Colour is never the only cue.** Field errors are text next to the field; the three error cards pair the tint with a `ShieldAlert`; the scope toggle pairs its colour with `aria-pressed` and a filled-vs-outline treatment. 1.4.1 passes. No fix.

### G. Motion, touch targets, meta

- **G1 — The AI panel ignores `prefers-reduced-motion` (2.3.3 AAA, and the round-4 policy).** The `globals.css` policy only reaches CSS animations; `framer-motion` (`add-joke/page.tsx:294-346`) animates opacity and 20px of travel per card in JS, on every generation, for everyone.
- **G2 — The 24px floor from round 5 holds (2.5.8 AA).** Audited app-wide: chip × 24px, toast close 24px, interactive stars 36px, all `size="sm"` buttons 36px, `Switch` 24×44, `CommandItem`/`SelectItem` ~32px, the auth reveal button 40px. The only sub-24px target is the `Slider` thumb at 20px, which **passes via the spacing exception** — no other target's 24px circle intersects it. **No offenders.** Recorded so it stays true.
- **G3 — `html lang="en"` is set** (`layout.tsx:35`). ✅
- **G4 — Page titles: see C2.** One title for seven routes.
- **G5 — `<footer>` nested in `<main>`.** `page.tsx:119` is inside the layout's `<main>`, so it is not exposed as a `contentinfo` landmark. Deliberately not fixed — see the deferrals.

### Deliberately deferred (documented in Task 16, not implemented)

- **A dangling `aria-describedby` in `ui/form.tsx:116-120`.** `FormControl` always references `${id}-form-item-description`, and most fields render no `<FormDescription>`. - **Removing `framer-motion` from `add-joke/page.tsx`.** Fourth round. Task 9 makes it honour reduced motion and leaves it there.
- **A visible "required" marker on form labels.** Task 7 adds `aria-required`; the visible convention in this app is to mark the *optional* field, which is unambiguous when exactly one field is optional.

### Task 4: Card titles become real headings

**Objective:** Closes **A3**. Five pages currently have exactly one heading each.

`CardTitle` renders a `<div>` by design — correct for a card that is not a section of the page, wrong for the nine cards that are. Rather than hand-rolling `<h2>` at each call site (which would fork the card-title scale round 5 spent a task unifying), `CardTitle` gains an `as` prop.

**Files:**
- Modify: `src/components/ui/card.tsx`, `src/components/EmptyState.tsx`, `src/app/add-joke/page.tsx`, `src/app/edit-joke/[jokeId]/page.tsx`, `src/app/joke/[jokeId]/page.tsx`, `src/components/csv-import.tsx`, `src/components/joke/ExplanationCard.tsx`, `src/components/joke/RatingForm.tsx`, `src/components/joke/CommunityRatings.tsx`

**Steps:**

1. In `src/components/ui/card.tsx`, replace the `CardTitle` block (`:32-45`) with:

```tsx
interface CardTitleProps extends React.HTMLAttributes<HTMLHeadingElement> {
  /**
   * Element to render. `div` — shadcn's original — is right for a card whose
   * title is not a section of the page. Pass `h1`/`h2`/`h3` when the card *is*
   * a section: with everything a div, `/joke/[jokeId]` and `/add-joke` had one
   * heading each and no outline for a screen reader to navigate.
   */
  as?: 'div' | 'h1' | 'h2' | 'h3';
}

const CardTitle = React.forwardRef<HTMLHeadingElement, CardTitleProps>(
  ({ className, as = 'div', ...props }, ref) => {
    // Widened to `ElementType` on purpose: a union of intrinsic tags in JSX
    // position makes TypeScript resolve the ref against every member at once
    // (HTMLDivElement *and* HTMLHeadingElement), which no single ref satisfies.
    const Comp = as as React.ElementType;

    return (
      <Comp
        ref={ref}
        className={cn(
          "text-2xl font-semibold leading-none tracking-tight",
          className
        )}
        {...props}
      />
    )
  }
)
CardTitle.displayName = "CardTitle"
```

2. In `src/components/EmptyState.tsx`, add the same escape hatch for the one page whose entire content is an empty state. Add to `EmptyStateProps`:

```tsx
  /** Element for the headline. `p` by default — an empty state nested in a page
   *  that already has headings is not itself a section. `h1`/`h2` for the
   *  "joke not found" page, where this block *is* the page. */
  titleAs?: 'p' | 'h1' | 'h2';
```

Destructure it (`titleAs = 'p'`) and replace the title line (`:55`) with:

```ts
 * the page's status region, built once here.

 * Strings only: `src/lib/` is outside Tailwind's content globs
 * (`tailwind.config.ts`), so nothing here may return a class name.

export interface SkippedRow {
  /** 1-based line number in the uploaded file, blank lines included. */
  lineNumber: number;
  reason: string;
}

/** How many individual row numbers to name before summarizing the rest. */
export const MAX_REPORTED_ROWS = 10;

/**
 * `rows 4, 19, 27 and 3 more (missing "text" or "category")` — the row numbers
 * as the user sees them in their file, plus every distinct reason.
 */
export function describeSkippedRows(skipped: SkippedRow[]): string {
  const listed = skipped.slice(0, MAX_REPORTED_ROWS).map((row) => row.lineNumber);
  const remainder = skipped.length - listed.length;
  const rowList = `row${skipped.length === 1 ? '' : 's'} ${listed.join(', ')}${remainder > 0 ? ` and ${remainder} more` : ''}`;
  const reasons = Array.from(new Set(skipped.map((row) => row.reason)));
  return `${rowList} (${reasons.join('; ')})`;
}

 * skipped, nothing landed because there was nothing to land.
 */
export function summarizeImport(importedCount: number, skipped: SkippedRow[]): ImportSummary {
  if (importedCount > 0) {
    return skipped.length > 0
      ? {
          title: 'Import finished with skipped rows',
          description: `${importedCount} imported, ${skipped.length} skipped — ${describeSkippedRows(skipped)}.`,

          title: 'Import finished',
          description: `${importedCount} joke${importedCount === 1 ? '' : 's'} imported.`,

        title: 'Nothing imported',
        description: `No jokes imported — all ${skipped.length} row${skipped.length === 1 ? '' : 's'} skipped: ${describeSkippedRows(skipped)}.`,

        title: 'Nothing imported',
        description: 'No valid jokes found in the CSV file to import.',

}
```

```ts
/**
 * What the feed says when "Load More" has appended a page.
 *
 * Counting alone is not enough to tell an append from a filter change: both
 * change the number of cards on the page. A count is only comparable against
 * another count taken for the *same* filter set, so the key travels with it.
 *
 * Strings only: `src/lib/` is outside Tailwind's content globs.
 */
export interface FeedCountSnapshot {
  /** The serialized filter set these results answer (`filtersToSearchParams`). */
  key: string;
  /** How many jokes were on the page. */
  count: number;
}

/**
 * The announcement for the transition `previous` → `next`, or `''` when there
 * is nothing to announce. Empty for: the first snapshot ever; a different
 * filter set (that is a new result set, not an append); the first page of a
 * filter set (the page painting for the first time is not "more"); and any
 * transition that did not grow.
 */
export function describeFeedAppend(
  previous: FeedCountSnapshot | null,
  next: FeedCountSnapshot
): string {
  if (!previous) return '';
  if (previous.key !== next.key) return '';
  if (previous.count === 0) return '';
  if (next.count <= previous.count) return '';

  const added = next.count - previous.count;
  return `${added} more joke${added === 1 ? '' : 's'} loaded. ${next.count} now showing.`;
}
```

```ts
/**
 * Keyboard arithmetic for a star-rating radio group (ARIA APG "radio group",
 * which selects on arrow navigation rather than on a separate commit).
 *
 * Pure integers in, pure integers out: `src/lib/` is outside Tailwind's content
 * globs and this returns no markup and no class names.
 */

/**
 * The rating a key press moves to, or `null` when the key is not one this
 * widget handles (so the caller can leave the event alone).
 *
 * Both axes are wired: a horizontal row of stars is read horizontally by a
 * sighted user and vertically by a screen reader in forms mode. Movement wraps,
 * per the APG, which is also what makes `current === 0` — nothing chosen yet —
 * land on 1 going forward and on `maxStars` going back.
 */
export function ratingFromKey(key: string, current: number, maxStars: number): number | null {
  if (maxStars < 1) return null;

  switch (key) {
    case 'ArrowRight':
    case 'ArrowUp':
      return current >= maxStars ? 1 : current + 1;
    case 'ArrowLeft':
    case 'ArrowDown':
      return current <= 1 ? maxStars : current - 1;
    case 'Home':
      return 1;
    case 'End':
      return maxStars;
    default:
      return null;
  }
}

/**
 * Which star is the group's single tab stop (roving tabindex): the chosen one,
 * or the first when nothing is chosen yet — the APG's rule for an unset radio
 * group. Guards a fractional or out-of-range `rating`, which the read-only
 * branch supports and which could otherwise leave the group with no tab stop
 * at all.
 */
export function tabbableStarIndex(rating: number, maxStars: number): number {
  if (!Number.isFinite(rating)) return 0;
  const rounded = Math.round(rating);
  return rounded >= 1 && rounded <= maxStars ? rounded - 1 : 0;
}
```

### Task 15: A route change moves focus to the page

**Objective:** Closes **D2**.

The App Router leaves focus where the link was, on a node that no longer exists. Task 3 made the *title* audible; this makes the keyboard position follow. Both are needed: the announcer fires only when the title string changes, so joke-to-joke navigation is announced by nothing at all, and this is what covers it.

**Files:**
- Create: `src/components/RouteFocus.tsx`
- Modify: `src/app/layout.tsx`

**Steps:**

1. Create `src/components/RouteFocus.tsx`:

```tsx
"use client";

import { useEffect, useRef } from 'react';
import { usePathname } from 'next/navigation';

/**
 * Moves focus to the `<main>` landmark on each client-side route change.
 *
 * The App Router does not move focus, so after clicking a nav link the keyboard
 * position is still on a node the new page does not contain — the next Tab
 * resumes from wherever the browser decides, usually the top of the document,
 * with no announcement that anything happened.
 *
 * Deliberately keyed on `pathname` only: `/jokes` re-navigates to itself on
 * every filter change (`useJokeFilters` pushes a new query string), and pulling
 * focus out of the toolbar each time a chip is removed is exactly the bug Task
 * 13 fixes.
 */
export default function RouteFocus() {
  const pathname = usePathname();
  const isFirstRender = useRef(true);

  useEffect(() => {
    // The first render is the initial page load: the browser has already put
    // focus where it belongs and stealing it would break "start reading at the
    // top" for a screen reader.
    if (isFirstRender.current) {
      isFirstRender.current = false;
      return;
    }

    // `preventScroll`: the router has its own scroll handling, including
    // restoring the previous position on Back. Focusing without it would jump
    // to the top of the page and undo that.
    document.getElementById('main-content')?.focus({ preventScroll: true });
  }, [pathname]);

  return null;
}
```

2. In `src/app/layout.tsx`, import it and render it immediately after `<Navbar />`:

```tsx
              <Navbar />
              <RouteFocus />
```

**Behaviour change:** after a client-side navigation, the next Tab starts at the top of the page content rather than at the top of the nav. `<main>` carries `outline-none` (Task 1), so nothing is drawn.

**Verification:**
```bash

grep -n "RouteFocus" src/app/layout.tsx   # 2 hits (import + usage)
```

On `/jokes`, remove a filter chip — focus stays on the next chip (Task 13 still holds; the pathname did not change). Navigate Back from a joke — the scroll position is still restored.
